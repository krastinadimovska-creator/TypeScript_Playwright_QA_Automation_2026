Helpers Flow how a test calls plain functions, passes them page, and why they remember nothing

  • 1. A helper is a plain exported function: import it and call it
  • 2. It gets page and test data as arguments, every time
  • 3. It keeps no state: arguments live only while it runs
  • 4. Action helpers act; locator helpers return a Locator for expect in the test
What is a functional helper? The basics in 2 minutes click or press I to show / hide

1. The idea in one sentence

A functional helper is a plain exported function that takes page (and test data) as arguments and does one user action, or returns one Locator.

Analogy: a recipe card. It tells you the steps, but you bring the kitchen (page) and the ingredients (data) every time.

2. Anatomy of a helper module

// helpers/tasks.ts
export function taskItem(page: Page, title: string): Locator {
  return page.getByRole('listitem').filter({ ... });
}

export async function addTask(page: Page, title: string) {
  await page.getByLabel('New task').fill(title);
  await page.getByRole('button', { name: 'Add task' }).click();
}

// tests/tasks.spec.ts
import { addTask, taskItem } from '../helpers/tasks';
await addTask(page, 'Buy milk');

4. When does a helper run?

  • Only when you call it. There is no setup: import it and call it.
  • Arguments live only during the call. When it returns, it forgets everything.
  • Nothing is created per test, so there is nothing to clean up and no state shared between tests.

5. What goes in, what stays out

  • In: page (or a Locator) and test data, as arguments.
  • In the helper: selectors and the click/fill steps.
  • Out: expect(...): keep it in the test.
  • Out: module-level variables like let currentPage: they break isolation.

6. Where helpers are used in real projects

NeedHelper example
Common actionslogin(page, user), logout(page), acceptCookies(page)
FormsfillAddress(page, address): one object of data, many fields
ComponentspickDate(datePicker: Locator, '2026-05-01'): take a Locator, so it works for every date picker
Tables and listsrowByText(page, 'Alex') returns a Locator for assertions
API setupcreateUser(request, data) with Playwright's request instead of page

7. Why use helpers?

  • Very little code: no class, no constructor, no this.
  • Easy to compose: helpers call helpers.
  • Explicit: the call shows every input.
  • Safe to pass around: no this to lose.

8. Watch out for

  • page in every call: repetitive in long tests.
  • Flat namespace: many imports, name clashes. import * as tasks from helps.
  • No encapsulation: nothing stops raw selectors in tests.
  • One giant utils.ts: group helpers by page or feature.

Rule of thumb: a helper does one thing, gets everything it needs as arguments, and remembers nothing.
